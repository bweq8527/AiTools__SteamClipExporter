# 导出目录生效与音画同步修复

日期：2026-10-29。来源：用户报告选择输出文件夹后必须再次扫描才生效，以及导出 MP4 音画不同步。本次授权为缺陷修复；旧初始化任务的 Markdown 限定不适用于本任务。

## 目标与验收

- 选择或手填导出目录后，无需再次点击扫描，后续新入队任务使用该目录；已入队任务保持原路径。
- 保留源音视频时间戳的相对关系；隔离合成分段测试覆盖不同起点、无音频与长时间戳。真实素材的主观同步仍需样例验收。
- 不安装依赖、不操作 Git 写命令、不改用户真实媒体；保持 MP4 流复制及现有命名。

## 调查与方案

- 基线：`main`，HEAD `b70cbc4`，开始时 `git status --short --branch` 无修改。旧快照停留在 `3e930fc`，本轮重新核对。Git 所有权限制使用单次只读 `safe.directory` 参数处理。
- 目录根因：`browse()` 只写输入框；`EXPORT_PATH` 仅由扫描按钮的 `setP()` 提交。
- 音画假设：FFmpeg 默认分别归零两个输入，丢失源时间轴偏移；先生成分段并探测包时间戳验证，不凭症状加固定延时或重编码。
- 新增 `/api/set_export_path` 仅更新导出路径，不要求再次扫描素材；提取串行路径请求供扫描、导出目录更改与入队使用；失败不入队。路径更改刷新已导出标记。
- 方案调整原因：复用 `set_path` 会连带应用尚未扫描的素材输入框，并且不能先选择输出目录；独立接口保留素材库和已排队路径。原 `set_path` 的兼容回退规则保留，新接口对非空无效目录返回 400。
- 合成 DASH 已确认默认命令把相差 0.728 秒的两输入分别归零。最终音频输入使用 `-isync 0` 参考视频起点，输出端 `-avoid_negative_ts make_zero` 统一平移，继续流复制；不加固定偏移或重编码。
