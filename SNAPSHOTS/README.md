## 用户以后要求恢复 v2.5 等现存命名版本时

这是一项需要助手实际执行并核验的约定，不是后台自动恢复功能；不能保证不读取规则的其他工具会自动遵循。

1. 读取本登记和所选版本清单。先检查该版本 project.zip 与 manifest.json 的 SHA-256 等于对应版本小节中的固定值，再验证所有归档成员与清单逐字节一致；有损坏／缺失立即停止，不能凭聊天记忆或功能描述重新生成。
2. 只读核对 Git 和当前工作区。暂停会写入项目的应用／任务，避免运行中重写文件。先把当前工作区保存到 SNAPSHOTS 内的新备份，验证后再覆盖；不执行 Git reset、checkout、restore、clean、commit 等写操作。
3. 恢复前检查所有归档路径：禁止绝对路径、`..` 越界、大小写冲突、符号链接／重解析点；解析后的每个目标必须位于当前项目根目录，且不触碰 `.git`、`SNAPSHOTS`。
4. 按清单原样还原文件和目录。对于当前存在而清单没有的文件／目录，先移入 SNAPSHOTS 内本次恢复的隔离备份，不能只覆盖旧文件而留下新代码，也不要直接永久删除。写入／移动前验证绝对目标边界。
5. 检查恢复后的所有文件 SHA-256、大小、完整文件集合和目录集合等于 manifest；排除根 `.git`、`SNAPSHOTS`，除此之外不能有新增文件。逐文件一致而存在额外文件，不算精确恢复。
6. 校验完成后不要运行会写缓存的应用或测试、不要格式化或改写已还原的记忆文档。恢复证据、时间、备份位置、校验结果只写入 SNAPSHOTS 内的恢复记录，避免刚恢复就修改版本内容。若用户随后授权开发，需说明已离开该精确快照状态。
7. 最终报告文件／目录数和校验结果，明确只保证上述范围；任何锁定文件、写入失败、未隔离新增文件或校验差异均须报告，不能声称完全恢复。

只要实际照此完成并验证，就能确认文件范围内原样一致；本登记本身不会自动执行这些步骤。
